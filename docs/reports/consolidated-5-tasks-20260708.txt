TASK 5 — Investigate the two migration runs (held item 6)
================================================================================
STATUS: DONE. Real, confirmed finding. Nothing deleted.

Both migration_runs rows target the SAME collection, buddhism_v2:
  b7a2d470-...  started 2026-06-24T13:57:24Z, status=PHASE_B_COMPLETE,
                completed_at=NULL (abandoned — the "06-24" run)
  80dfb711-...  started 2026-06-27T03:22:54Z, status=PHASE_D_COMPLETE
                (the "06-27" run that completed normally)

Root cause identified in code: core/migration.py's _migrate_batch
generates point IDs via `uuid.uuid4()` — random, not derived from source
content (doc_id/chunk_index/hash). phase_b itself has no resume/skip logic
— it unconditionally re-embeds and upserts every chunk from the source
collection every time it runs, regardless of what a prior run already
wrote. Combined, these two facts mean: if the abandoned run's Phase B
actually wrote real data before stalling, and the second run's own Phase B
then reprocessed the same source data fresh, Qdrant's upsert-by-ID
idempotency could not have caught it — different random UUIDs for the same
underlying chunk both persist as separate points.

Verified this empirically, not just from code reasoning — scrolled the
full buddhism_v2 collection (1,126,601 points, ~66s with the source_pdf
payload index from Task work earlier today) and counted occurrences of
each (source_pdf, chunk_index) pair:

  distinct (source_pdf, chunk_index) pairs:  925,306
  pairs appearing MORE THAN ONCE:            190,243
  total points involved in duplication:      391,538
  excess/orphaned points (true duplicates):  201,295

Roughly 20.6% of unique source chunks exist twice in buddhism_v2 right
now, each duplicate carrying a distinct random point ID and therefore
invisible to any ID-based dedup. Example duplicates (verbatim from the
scroll, confirming these are real books, not synthetic/test data):
  "Mipham's Dialectics and the Debates on Emptiness..." (Karma Phuntsho),
    chunk 223, x2
  "Mahaprajnaparamitasastra - Vol. 4" (Nagarjuna), chunk 179, x2
  "The Precious Treasury of Philosophical Systems" (Longchen Rabjam),
    chunk 649, x2
  "Treasury of Genuine Meaning - V3" (Longchen Rabjam), chunk 2882, x2

This is exactly the class of problem Task 4's new payload-integrity check
(above) is built to catch — had it existed on 2026-07-02, Phase C would
have failed this migration rather than reporting it verified.
